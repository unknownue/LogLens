# CSV / TSV 表格预览（表格视图的文本后端）

`.csv` / `.tsv` 文件打开即进**表格视图**：按分隔符解析成行列，粘性表头 + 虚拟滚动，
列宽按内容自适应。这是「表格视图」的**文本**后端；同一个入口还带着二进制那一个
（`.bin` → GM10 `client_cfg` 配置表），两者按扩展名分工。

```
                      ┌────────────────────────── 视图模式：table ──────────────────────────┐
   .csv / .tsv ──────▶│  tableKindOf(path) === "csv"  → csv-table 页（本文件）              │
   .bin        ──────▶│  tableKindOf(path) === "cfg"  → cfg-table 页（client_cfg + schema）│
                      └──────────────────────────────────────────────────────────────────────┘
```

## 为什么是一个入口、两种后端

用户想的是「把这个文件按表格看」，而不是「用哪个解析器」。所以视图模式弹窗里只有
一项「表格视图」，**后端由扩展名决定**（`src/views/table-kind.ts::tableKindOf`）：

| 文件 | 后端 | 需要 schema | 说明 |
|------|------|------------|------|
| `.bin` | `cfg`（二进制） | 是 | MemoryPack 序列化的配置表，见 [client_cfg_bin_format.md](client_cfg_bin_format.md) |
| 其余（`.csv` / `.tsv` / 手切进来的 `.txt` / `.log`） | `csv`（文本） | 否 | 按分隔符解析 |

`.bin` 不能当文本解析（二进制只会得到一屏乱码），CSV 也不该被要求先选 schema
（那套结构描述只有 MemoryPack 才有意义）。视图模式弹窗里的 schema 记录区因此只在
`.bin` 文件上出现。

## 默认视图模式

| 扩展名 | 打开时的视图 | 理由 |
|--------|-------------|------|
| `.md` / `.markdown` | Markdown 预览 | 文档要看排版 |
| `.csv` / `.tsv` | **表格视图** | CSV 本身就是行列数据，用文本视图看是一屏逗号长行 |
| 其余 | 文本视图 | 日志的主力形态；`.bin` 因为依赖 schema 也留在这里手动切 |

判定这条规则的是 `App.defaultViewModeFor`（`isMarkdownPath` → md、`isTablePath` → table、
其余 text）；所有打开入口都经过它：文件对话框、拖放、命令行参数、最近打开、
会话恢复（老存档的例外见下）。

文本视图一直是表格页工具栏最左侧的那个图标按钮 —— 想看原文点一下就回去，
`Ctrl+F` / 过滤 / 跟随都还在那边。

### 升级迁移：老会话里的 CSV 也要进表格视图

会话存档（`lv-tabs`）里的 `modes` 记的是「每个 tab 当时处于哪个模式」，**是记录，不是
用户意图**。0.5.0 及更早的版本里表格视图只服务 `.bin`，`.csv` 打开就是文本视图 ——
那些存档里的 `"text"` 是**当年的默认值**。直接照抄会让升级后老会话里的 CSV 一直停在
文本视图，正好与「CSV 默认表格」相反。

所以存档从 0.6.0 起带一个 `version` 字段，恢复时按 `isStaleDefaultMode`
（`src/views/table-kind.ts`）判断：

| 存档 | 该 tab 记的模式 | 恢复成 |
|------|----------------|--------|
| 老存档（无 `version`） | `text`，路径是 `.csv` / `.tsv` | **表格视图**（按新默认重新推断） |
| 老存档 | 别的模式（如用户当年手动切到 `md`） | 照旧 |
| 新存档（`version: 2`） | `text` | 照旧 —— 那是用户自己选的 |

判定规则是纯函数，`tools/verify-csv.test.mjs` 逐条钉住；端到端脚本里也有两段
（老存档迁移 / 新存档尊重选择）。

## 数据流

```
App.openPath(path)
  └─ defaultViewModeFor(path) → "table"
       └─ parseCsv(tabId, path)                    ← App.tsx
            └─ invoke("parse_csv_table", {path, delimiter, encoding})
                 └─ src-tauri/src/csv_table.rs     ← 流式读 + 增量解码 + 状态机
                      └─ CsvTable { rows, width, delimiter, truncated, max_rows, bytes, encoding }
           → setCsvTables[tabId]
                └─ CsvTableTab（src/views/CsvTableTab.tsx）
                     └─ csv-model.ts：切表头/数据、列宽、单元格显示、复制
                          └─ TableGrid（src/views/TableGrid.tsx）：粘性表头 + 虚拟行
```

**表头 / 数据的分界在前端**：后端只回一份「行矩阵」（含首行，行长度可能不等）。
好处是「首行为表头」开关是纯前端状态 —— 切一下不用重读文件、不用重新解析，
`Ctrl`-级的操作在两百万行的表上也瞬间完成。

## 后端（`src-tauri/src/csv_table.rs`）

**为什么解析放后端**：

1. **编码**：CSV 大量来自 Excel 导出，国内环境里 GBK/GB18030、带 BOM 的 UTF-8、
   UTF-16（PowerShell `Out-File`）都很常见。复用 `encoding.rs` 那一层，与文本视图 /
   Markdown 预览是同一套探测与手动选择 —— 整篇解错编码的表格是「乱码表格」，
   比打不开更误导人。
2. **大文件**：几百 MB 的 CSV 不能整篇跨 IPC 交给前端再解析（解析在主线程，界面会卡住，
   内存峰值也由前端承担）。读取时就按上限截断，只把预览需要的那部分交出去。

**解析规则**（RFC 4180 的宽松实现，手写状态机，不引 `csv` crate）：

- 字段可用 `"` 包裹；引号内的分隔符与换行都是字面内容；`""` 表示一个字面引号。
- 换行接受 `\n`、`\r\n`（Windows / Excel）与单个 `\r`。
- **空行跳过**（Excel 导出常带尾随空行；渲染成一行空表格没有意义）。
- 畸形输入（引号未闭合、引号后还有字符）按字面继续解析，不报错 —— 预览的价值是
  「看到内容」，不是替用户判定文件不合法。
- **不做类型推断**：所有单元格都是字符串（`00123` 的前导零必须留着）。
- 读取是流式的：256 KiB 一块 → 编解码器增量解码（跨块的多字节序列由 `encoding_rs`
  自己缓冲）→ 状态机。**解码目标串必须先预留容量**：`Decoder::decode_to_string`
  不负责扩容，空 `String` 会让它立刻返回 `OutputFull` 且一个字节都不写
  （症状是「文件读到了但一行都没解析出来」）。

**两个上限**（都只影响预览长度，不是错误）：

| 常量 | 默认 | 作用 |
|------|------|------|
| `DEFAULT_MAX_ROWS` | 200 000 行（含首行） | 行数闸门 |
| `DEFAULT_MAX_BYTES` | 32 MiB（**解码后**文本） | 列很多 / 单元格很长时兜底 |

任一触顶 → `truncated: true`，前端在表格上方显示一条横幅说明只解析了文件的前 N 行。
判定「是否真的截断」看三处证据（状态机丢掉过输入 / 当前读块还有没喂进去的字节 /
文件还有字节）—— 只看「文件还有没有」会把「小文件在一个 256 KiB 块内就触顶」误报成
没截断（见 `cargo test --lib csv_table` 里的 `row_cap_truncates_and_reports_more_data`）。

**错误文案契约**（前端 `classifyOpenError` 按文案分流，措辞只能有一处定义）：
`文件不存在: <path>`（不存在 / 是目录，与 `document.rs` 共用 `require_file`）、
`读取失败: <io error>`（权限等）、`不支持的分隔符: …`（防御）。

## 前端

| 关注点 | 做法 |
|--------|------|
| 页内查找 | `Ctrl+F`（或工具栏「查找」）打开右上角查找框：命中计数、`Enter` / `Shift+Enter`（或 ↑↓）循环步进、当前命中滚到可视区中部并把那一列横向拉进视野；`Aa` 区分大小写、`ab|` 全字匹配。命中片段用与文本视图同一套配色（靛蓝实心块 / 当前命中品红 + 亮环） |
| 分隔符 | 工具栏下拉：逗号 / 制表符 / 分号 / 竖线。`.tsv` 默认制表符，其余默认逗号；手动改过的值随会话存档持久化。后端不限制死集合（接受任意单字符） |
| 首行为表头 | 工具栏勾选框，默认开。纯前端切换（不重读文件）；空列名或未勾选时列名生成为「列1/列2…」（英文 `Col1`） |
| 参差行 | 后端不补齐行（省 IPC 体积）；列数取 `max(表头长度, 全表最长行)`，取不到的单元格按空串渲染 —— 数据行比表头长时多出来的列照样画出来 |
| 单元格换行 | 行高固定（虚拟滚动按固定行高布局），单元格里的换行 / 制表符显示为 `␊` / `⇥`，完整原文在悬停提示里 |
| 列宽 | 按表头 + **均匀采样**最多 2000 行估算（20 万行 × 20 列全扫要几百万次文本测量，会让打开文件明显卡一下）。代价：某列只有没被采样到的行特别长时，会被上限（600px）截断显示 |
| 复制当前视图 | TSV（表头 + 全部数据行），单元格内的制表符 / 换行替换成空格，保证粘进 Excel 仍是一格一行 |
| 不跟随文件变化 | 表格不做轮询：文件被外部改过后点工具栏的「重新解析」（与错误面板里的那个按钮是同一个动作） |
| 状态栏行数 | 上报**数据行数**（勾了表头时不含首行）；编码可点开切换（CSV 是文本，与 Markdown 同构：换编码 = 带新编码重新解析） |

共享件：网格本身（粘性表头、虚拟行、列宽对齐、`.cfg-*` 样式）抽在
`src/views/TableGrid.tsx`，配置表页与 CSV 页共用一份 —— 两份拷贝最容易出的问题是
其中一份改行高时忘了同步，表现为一个视图滚动条对得齐、另一个对不齐。
查找的匹配语义（子串 / 大小写 / 全字）与文本视图共用 `src/search/matcher.ts`，
命中扫描在 `src/views/csv-search.ts`（都是纯函数，`node --test` 直接覆盖）。

## 已知取舍

- **查找扫的是已加载的整份表**：与文本视图不同，表格的数据本来就在前端（上限
  20 万行），所以查找不需要后端命令 —— 但一次全扫（行 × 列个单元格）在大表上要
  几十到几百毫秒，因此：搜索词走 `useDeferredValue`（打字先回显、计数稍后跟上）、
  命中数封顶 5000（计数显示成 `5000+`，命中位置真正的作用是「跳过去看」）。
- **查找只认完整单元格文本**：命中判定作用在单元格的原始文本上（含被显示成 `␊` / `⇥`
  的换行与制表符），不是渲染后的可见文字。所以搜 `line1` 能找到含换行的单元格，
  但搜 `line1␊line2` 找不到（那个 `␊` 只是显示层的记号）。
- **不跟随文件变化**：CSV 表没有自动刷新（Markdown 预览有）。文件被覆盖后要手动
  「重新解析」（表格页工具栏最右侧的按钮）。
- **分隔符是单字符**：不支持多字符分隔符（如 `||`），也不做自动探测 —— 探测错的概率
  不低，而用户会不知道表格为什么长这样。选错了换一下即可。
- **截断就是截断**：超过 20 万行只解析前 20 万行。要看完剩下的部分请切文本视图
  （那边是按需稀疏读取）。
- **不推断类型**：数字 / 日期都按原文显示，不做右对齐、不做数值排序（表格视图本来
  也不排序）。

## 验证

```powershell
cd src-tauri && cargo test --lib csv_table   # 解析器：引号 / CRLF / 编码 / 上限 / 错误文案（22 例）
node --test tools/verify-csv.test.mjs        # 表种与分隔符规则、表头切分、显示、TSV、列宽、查找扫描（30 例）
node --test tools/verify-body-views.test.mjs # 页面优先级：csv-table / cfg-table / 状态页的先后
node tools/verify-search-frontend.mjs        # 匹配语义与后端口径一致（直接 import 真实现）
node tools/e2e-csv.mjs --launch              # 浏览器端到端（需先 pnpm run dev）
```

端到端脚本覆盖：`.csv` 打开即表格（且**不**建文本会话）→ 表头开关不重新解析 →
换分隔符真的重新解析且列数跟着变 → 「重新解析」按钮重读一次 → 复制为 TSV →
切回文本视图（补 `open_log_file`）→ 再切回表格 → `.tsv` 按扩展名用制表符 →
`.log` 仍从文本视图起步 → 截断横幅 → 在表格页换编码（重新解析，**不**走
`set_encoding`）→ 刷新页面后视图模式、分隔符与编码选择一起恢复 → 老存档迁移 →
新存档的显式文本视图被尊重 → **查找**（Ctrl+F 开框并聚焦、命中计数、远处行滚进
可视区、命中列横向拉进视野、Esc 关闭、Enter/Shift+Enter 循环、Aa 与 ab| 改变命中数）。

打包版冒烟（`node tools/smoke-release.mjs`，需先 `make loglens-build`）里也有一条
CSV 断言（H），走的是**真实 Tauri IPC + 真实解析器**：UTF-8 + BOM 的引号/多行/空字段
样例要逐格还原（BOM 没剥掉时首列表头会变成 `\uFEFFname`），GBK 样例要按兜底编码
解出中文 —— 这类「命令名 / 参数名 / 编码探测」的接线错误在 mock 后端的 E2E 里看不见。

手工验收样本：[`repro/sample.csv`](../repro/sample.csv) 带引号字段、字段内逗号、
字段内换行、`""` 转义、空字段与中英文混排；[`repro/sample.tsv`](../repro/sample.tsv)
用来确认 `.tsv` 的默认分隔符是制表符。两个文件都可以直接拖进窗口打开。
